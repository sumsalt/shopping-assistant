# 需求文档

## 引言

本需求文档描述了购物助手应用的登录认证功能。该功能旨在为系统提供基于配置文件的用户身份验证能力，不提供注册功能，仅允许预配置的账号登录系统。登录后，用户可以访问所有页面和 API 接口；未登录用户将被重定向到登录页面。

### 技术背景
- 前端框架：Nuxt.js (Vue 3)
- UI 样式：TailwindCSS
- 后端：Nuxt Server API (Nitro)
- 用户数据存储：配置文件（JSON/YAML 格式）

## 需求

### 需求 1：用户配置文件管理

**用户故事：** 作为一名系统管理员，我希望通过配置文件管理可登录的用户账号，以便在不修改代码的情况下灵活管理用户权限。

#### 验收标准

1. WHEN 系统启动 THEN 系统 SHALL 从配置文件中加载用户列表
2. IF 配置文件不存在或格式错误 THEN 系统 SHALL 记录错误日志并使用默认的空用户列表
3. WHEN 管理员修改配置文件 THEN 系统 SHALL 在下次请求时读取最新的用户配置（无需重启）
4. 每个用户配置项 SHALL 包含以下字段：
   - `username`：用户名（字符串，必填，唯一）
   - `password`：密码（字符串，必填，建议使用哈希存储）
   - `email`：邮箱地址（字符串，必填，用于显示和潜在的通知功能）

#### 配置文件示例格式
```json
{
  "users": [
    {
      "username": "admin",
      "password": "hashed_password_here",
      "email": "admin@example.com"
    }
  ]
}
```

### 需求 2：用户登录功能

**用户故事：** 作为一名用户，我希望通过用户名和密码登录系统，以便访问受保护的功能和数据。

#### 验收标准

1. WHEN 用户访问登录页面 THEN 系统 SHALL 显示包含用户名和密码输入框的登录表单
2. WHEN 用户提交正确的用户名和密码 THEN 系统 SHALL 创建会话并重定向到首页或用户之前请求的页面
3. IF 用户提交的用户名不存在 THEN 系统 SHALL 显示"用户名或密码错误"的错误提示
4. IF 用户提交的密码不正确 THEN 系统 SHALL 显示"用户名或密码错误"的错误提示（与用户名不存在显示相同错误，防止用户枚举攻击）
5. IF 用户名或密码字段为空 THEN 系统 SHALL 显示相应的验证错误信息
6. WHEN 用户成功登录 THEN 系统 SHALL 将用户信息（不含密码）存储在会话中

### 需求 3：用户登出功能

**用户故事：** 作为一名已登录用户，我希望能够安全地登出系统，以便保护我的账号安全。

#### 验收标准

1. WHEN 已登录用户点击登出按钮 THEN 系统 SHALL 清除用户会话并重定向到登录页面
2. WHEN 用户登出成功 THEN 系统 SHALL 使当前会话失效
3. 登出按钮 SHALL 在页面头部导航栏中显示，且仅对已登录用户可见

### 需求 4：页面访问控制

**用户故事：** 作为一名系统管理员，我希望所有页面都需要登录后才能访问，以便保护系统数据的安全性。

#### 验收标准

1. WHEN 未登录用户访问任何受保护页面 THEN 系统 SHALL 重定向用户到登录页面
2. WHEN 未登录用户被重定向到登录页面 THEN 系统 SHALL 记录原始请求的 URL，以便登录成功后跳转回原页面
3. WHEN 已登录用户访问登录页面 THEN 系统 SHALL 自动重定向到首页
4. 登录页面（`/login`）SHALL 是唯一不需要登录即可访问的页面

### 需求 5：API 接口访问控制

**用户故事：** 作为一名开发者，我希望所有 API 接口都需要认证后才能调用，以便防止未授权的数据访问。

#### 验收标准

1. WHEN 未认证的请求访问任何 API 接口（除登录接口外）THEN 系统 SHALL 返回 401 Unauthorized 状态码
2. WHEN 未认证的请求返回 401 THEN 响应体 SHALL 包含 `{ "code": 401, "message": "未授权，请先登录" }` 格式的错误信息
3. WHEN 已认证的请求访问 API 接口 THEN 系统 SHALL 正常处理请求并返回相应数据
4. 登录接口（`POST /api/auth/login`）和登出接口（`POST /api/auth/logout`）SHALL 不受此限制

### 需求 6：会话管理

**用户故事：** 作为一名用户，我希望系统能够安全地管理我的登录状态，以便在合理的时间内保持登录。

#### 验收标准

1. WHEN 用户成功登录 THEN 系统 SHALL 创建一个服务端会话，并通过 HTTP-only Cookie 维护会话标识
2. IF 会话超过配置的有效期（建议默认 24 小时）THEN 系统 SHALL 自动使会话失效
3. WHEN 用户在会话有效期内进行操作 THEN 系统 SHALL 刷新会话的过期时间（滑动过期）
4. 会话数据 SHALL 存储在服务端，Cookie 中仅存储会话 ID
5. 会话 Cookie SHALL 设置 `HttpOnly`、`Secure`（生产环境）和 `SameSite=Lax` 属性

### 需求 7：登录页面 UI 设计

**用户故事：** 作为一名用户，我希望登录页面美观且易于使用，以便获得良好的用户体验。

#### 验收标准

1. 登录页面 SHALL 包含以下元素：
   - 应用 Logo 或标题
   - 用户名输入框（带标签和图标）
   - 密码输入框（带标签、图标和密码可见性切换）
   - 登录按钮
   - 错误提示区域
2. 登录表单 SHALL 支持回车键提交
3. 登录按钮 SHALL 在提交过程中显示加载状态并禁用重复提交
4. 表单 SHALL 支持基本的客户端验证（非空检查）
5. 页面设计 SHALL 与现有应用风格保持一致（使用 TailwindCSS）
6. 页面 SHALL 支持响应式布局，在移动设备上正常显示

### 需求 8：安全性要求

**用户故事：** 作为一名系统管理员，我希望登录系统具有基本的安全防护措施，以便防止常见的安全攻击。

#### 验收标准

1. 密码 SHALL 在配置文件中使用 bcrypt 或类似算法进行哈希存储
2. 登录失败信息 SHALL 不透露具体是用户名还是密码错误（防止用户枚举）
3. API 接口 SHALL 对登录请求进行基本的速率限制（可选，建议每 IP 每分钟不超过 10 次）
4. 所有敏感操作 SHALL 通过 HTTPS 进行（生产环境）
5. 会话 ID SHALL 使用足够的熵（至少 128 位）生成

## 边界情况和异常处理

1. **配置文件损坏**：系统应能优雅地处理配置文件损坏的情况，记录错误并阻止所有登录直到配置修复
2. **并发登录**：同一账号允许在多个设备/浏览器同时登录
3. **会话丢失**：当服务器重启导致会话丢失时，用户需要重新登录
4. **浏览器关闭**：会话 Cookie 应设置合理的过期时间，浏览器关闭后会话仍可保持

## 非功能性需求

1. **性能**：登录验证应在 500ms 内完成
2. **可维护性**：认证逻辑应封装在独立的模块中，便于后续扩展（如添加其他认证方式）
3. **可测试性**：核心认证逻辑应有单元测试覆盖

## 技术实现建议

1. 使用 Nuxt 的 `middleware` 功能实现页面级别的访问控制
2. 使用 Nitro 的 `server/middleware` 实现 API 级别的访问控制
3. 使用 `useCookie` 和服务端存储（如内存或 Redis）管理会话
4. 配置文件建议放置在项目根目录的 `config/users.json` 或使用环境变量指定路径
